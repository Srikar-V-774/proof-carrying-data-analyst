# Proof-Carrying Data Analyst

## HACKX26PSI08

An AI-powered data analyst that answers natural-language questions over datasets while providing executable code and verification for numerical results.

---

## 📌 About the Project

The idea behind our project is simple: instead of completely trusting an AI model to give us a numerical answer, we make the AI generate the code required to calculate the answer.

The generated Python code is then executed on the actual dataset using Pandas. After getting the result, our system executes the analysis again and compares the results.

If both executions produce the same result, the answer is marked as **VERIFIED**.

If the required information is not available in the dataset, the system can respond with **CANNOT DETERMINE** instead of guessing.

---

## 🎯 Problem We Are Solving

Normal AI data-analysis systems can understand questions and produce answers, but a numerical answer generated by an AI model is not automatically proof that the calculation was actually performed correctly on the dataset.

Our system focuses on:

* Correctness
* Reproducibility
* Executable analysis
* Verification
* Handling messy data
* Refusing when the required information is insufficient

The main idea is:

> **AI understands the question, Python performs the calculation, and the verifier checks the result.**

---

## 🚀 What Makes Our Project Different?

A normal AI data analyst can follow this flow:

```text
User Question
      ↓
AI Model
      ↓
Answer
```

Our system follows:

```text
User Question
      ↓
AI understands the question
      ↓
AI generates Python analysis code
      ↓
Python/Pandas executes the code
      ↓
Result is produced
      ↓
The analysis is executed again
      ↓
Results are compared
      ↓
Verified Answer
```

This means our answer is not based only on what the AI says.

The answer is connected to executable computation performed on the actual dataset.

## 🧠 How Our System Works

### 1. Data Upload

The user uploads a CSV or Excel dataset.

The backend loads the dataset using Python and Pandas.

### 2. Data Profiling

The system examines the dataset and identifies information such as:

* Number of rows
* Number of columns
* Column names
* Data types
* Missing values
* Duplicate rows
* Unique values
* Numeric ranges
* Sample records

### 3. Natural-Language Question

The user can ask questions such as:

```text
What is the total sales amount in the South region?
```

No SQL or programming knowledge is required.

### 4. AI Analysis

Gemini receives the question together with information about the dataset.

It determines which columns and operations are required and generates Python/Pandas code.

### 5. Code Validation

Before execution, the generated code is checked for invalid or unsafe operations.

Only the required data-analysis functionality is allowed.

### 6. Python Execution

The generated code is executed against the actual dataset.

Pandas performs the real calculation.

### 7. Verification

The same analysis is executed again.

For example:

```text
First Execution  → ₹XXXXXX
Second Execution → ₹XXXXXX

Result: MATCH
Status: VERIFIED
```

If the results do not match, the system does not confidently mark the answer as verified.

### 8. Final Answer

The user receives:

* The answer
* Generated analysis code
* Verification status
* Supporting dataset information

---

## 🛑 CANNOT DETERMINE

One important part of our system is that it should not invent an answer when the dataset does not contain enough information.

For example, if a user asks:

```text
What was the profit?
```

but the dataset contains only sales information and no cost/profit information, the correct response is:

```text
CANNOT DETERMINE
```

rather than producing a guessed number.

south = df[df["region"].str.strip().str.lower() == "south"]
result = south["total_amount"].sum()

## 🔐 API and AI Usage

This project uses the Gemini API for natural-language understanding and Python code generation.

The API key is stored locally in an environment file and is **not included in the repository**.

The generated code is validated before execution and restricted to the required data-analysis operations.

## 🎯 Project Goal

The goal of this project is to make AI-assisted data analysis more trustworthy.

Instead of asking users to simply trust an AI-generated number, we provide a chain of:

```text
Question
   ↓
AI Understanding
   ↓
Executable Code
   ↓
Actual Computation
   ↓
Re-execution
   ↓
Verification
   ↓
Answer
```

This makes the analysis more reproducible, explainable, and easier to verify.

---

## 📌 Scope

This is a hackathon prototype focused on demonstrating the core concept of proof-carrying data analysis.

The current implementation focuses on CSV/Excel-based analysis, data profiling, natural-language questions, executable Python/Pandas calculations, and result verification.
